## Design Specificity Verdict

**Authored — not category-interchangeable.** `app.css` documents a genuine "Adding Machine" system: warm near-black casing, amber phosphor figures, oxblood debit, and a vocabulary (tape, ledger, plate, figures, glow) specific to a personal ledger. The dashboard net-position `figures-glow` readout with its keypress flash is a signature moment; the `▮▯▯▯` blank-tape empty icon, 11px `plate` faceplate labels, and segmented VFD progress bars are cohesive and finance-native.

**Deterministic scan:** CLI detector clean — 0 findings across 272 files. Browser overlay (injected on 5 scans) found 3: `low-contrast` (real), `cream-palette` and `dark-glow` (false positives — both deliberate, documented tokens; dark-glow is scoped dark-only and reduced-motion-aware). The detector caught the light-mode contrast failure; it missed the systemic opacity bug below because the browser pass only exercised the onboarding surface.

**The authorship is being eaten by a rendering bug** — see Priority Issue 1.

## Overall Impression

Strong concept, compromised execution. The "Adding Machine" world is the best thing a finance app has done lately — then a single Tailwind/config defect silently deletes half of it. Fix the alpha rendering and the light-theme contrast and this becomes a genuinely distinctive product; leave them and it reads as a flat, half-finished shell of itself.

## What's Working

1. **A real design system, not a coat of paint.** Dual-theme token architecture with documented contrast engineering (`app.css:28-53`), Plex Mono tabular figures, the keypress `flash`, segmented VFD meters, and the dashboard net-position readout — a signature any finance app would want.
2. **Power-user efficiency is unusually complete.** `n` / `/` / Enter / Esc; a global quick-add window with fast amount parsing; session memory (last account/date); payee→tag rule learning; draft recovery.
3. **Microcopy and verb discipline.** "Add", "Save", "Delete", "Import 37 transactions", "Who did you pay?" — every action a verb, every empty state names its next step.

## Priority Issues

1. **[P1] Systemic: every Tailwind opacity modifier on a custom token renders transparent.** `bg-phosphor/10`, `bg-line/60`, `bg-tape/95`, `bg-debit/10`, `border-phosphor/30`, `hover:bg-line/40`, `placeholder:text-dim/*` — all compute to `rgba(0,0,0,0)` (~44 call sites). Root cause: `tailwind.config.ts:11-18` maps colors to `var(--x)` hex; Tailwind v3 can't apply alpha to a `var()` color, so the utility emits nothing. **Kills:** the active-nav tint, selected toggles, every progress bar's empty segments (a 0% budget is a hollow box), the mobile bottom-nav surface (`bg-tape/95` gone — labels float over scrolling content), budget banners, the future-tx badge, hover states, and placeholder text that falls back to default gray. **Fix:** define RGB-triplet vars (`--phosphor-rgb: 184 114 26`) and map `phosphor: 'rgb(var(--phosphor-rgb) / <alpha-value>)'`, or migrate to Tailwind v4 `@theme`.
2. **[P1] Light-theme primary actions and active states fail WCAG AA.** `#F4EFE2` on `#B8721A` = **3.35:1** (need 4.5:1) — every primary button and the FAB in light mode; active nav `text-phosphor` on ink is the same ratio. Dark theme passes (10.7:1). Light is what a fresh browser/web visitor gets. **Fix:** deepen light `--phosphor` to ≈`#9A5F00` or invert to dark text on amber.
3. **[P1] Destructive feedback is silent for assistive-tech users.** Delete is instant + 5s undo (no confirm, by design), but `GlobalToast.svelte` has no `role="status"`/`aria-live` — a screen-reader user hears nothing after deleting money data, and Undo is 12px amber text. **Fix:** `role="status"` + `aria-live="polite"`, and a real-size Undo target.
4. **[P2] No focus management in Modal, ContextMenu, or the autocomplete.** `Modal` opens `role="dialog" aria-modal="true"` but never moves/traps/restores focus (only the tx form is saved by an `autofocus`); `ContextMenu` is `role="menu"` that's never focused, no arrow-key nav, no `aria-haspopup`; the autocomplete listbox is mouse-only. Keyboard-only users can't reliably operate the two most-used popovers.
5. **[P2] Two identical search fields with different behaviors.** TopBar search (Enter → `/transactions?q=`) and the Transactions in-page field (needs a redundant "Search" button; Enter is dead). Same feature, divergent behavior, both visible. **Fix:** one global entry, page field submits on Enter (debounced), drop the button.

## Persona Red Flags

**Alex (power user):** `/` → lands on a second search field needing a button click — a redundant step on the fastest path. Editing a transaction's kind requires delete + recreate (kind disabled in edit). Single-item lists show two dead "← Previous / Next →" buttons. "Copy from previous" enabled with nothing to copy.

**Jordan (first-timer):** Onboarding Continue is enabled before any selection — skips choices he didn't know he was making. Budget rows' only edit affordance is a tiny dim figure with no hint ("click to set a budget" is invisible). Quick-add with no account: disabled amber input + "Something went wrong. Please try again" reads as broken, not "no account configured." Five transaction kinds as equal-weight buttons; Transfer/Refund/Adjustment unexplained.

**Sam (accessibility-dependent):** Light-mode primary buttons and active nav at 3.35:1 (fail AA); placeholders ~2.4:1. Delete→undo toast never announced (no aria-live). No focus trap in modal/menu; autocomplete is mouse-only. "VI" toggle has no aria-label (reads as "V-I"). Every budget row announces as an unnamed "progressbar 0%". Mobile More sheet: no dialog role, no focus management, no `aria-expanded`.

## Minor Observations

- Bottom-nav labels truncate ("Trans", "Budget") and mismatch the sidebar's full labels.
- Debts empty state's 🎉 and the currency-step flag emoji break the sober VFD register.
- FAB's amber glow ships in light mode where `app.css:73` says glow "reads muddy on paper."
- `break-all` on the net-position figure would shatter a very large balance across lines instead of scaling.
- The `▮▯▯▯` empty icon reused on Dashboard, Transactions, Accounts, and Goals — the signature wears thin.
- Settings language switch calls `location.reload()` — on the web build that wipes the in-memory DB and dumps the user back on onboarding.
- Budget month arrows are 28px, inline-edit ✓/✕ ~16px — below the stated 44px touch target.
- Progress bars, month nav buttons, and toggles mostly lack aria-labels/radiogroup semantics.
- Intermittent `Error: database not initialized — call initDb() first` race observed in the web/sql.js fallback (component `getDb()` vs `dbStore.init()`).
- The dashboard "Set up budget →" CTA is a 3.35:1 amber link competing with four other links on one screen.

## Questions to Consider

- Is the Adding Machine metaphor earning its keep or doing your thinking for you? If the amber phosphor were just an accent color, what would the interaction design actually be?
- You chose instant-delete-with-undo — a confident call. But the undo is invisible to screen readers and expired by navigation. Is 5s undo genuinely safer than a 300ms confirm for the Jordan-and-Sam majority?
- The web build forgets everything on reload — and on language switch. If web is a real target, "local-first" is false there; if it's only an E2E vehicle, every contributor's `pnpm dev` serves a surface that erases data mid-session. Which is it?
