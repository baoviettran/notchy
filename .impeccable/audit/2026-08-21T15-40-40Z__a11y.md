## Detailed Findings by Severity

### P1 Major — fix before release

**1. [P1] Light-mode amber text fails WCAG AA contrast**
- **Location**: `src/app.css` `html.light` block: `--phosphor: #B8721A`, `--phosphor-bright: #B8721A` (RGB triplets `184 114 26`); consumed by `Button.svelte:15` (`bg-phosphor text-ink`), `FAB.svelte:12`, `Sidebar.svelte:49/52` (`bg-phosphor/10 text-phosphor-bright` + `text-phosphor` icon).
- **Category**: Accessibility / Theming
- **Impact**: Primary buttons, the FAB, active nav, and the selected kind-toggle (TransactionForm) are unreadable for low-vision users in light mode — the default theme. Button text (`--ink` = paper `#F4EFE2`) on `#B8721A` measures **3.35:1**; active-nav amber `#B8721A` on the 10% tint measures **3.25:1**.
- **WCAG**: 1.4.3 (Contrast, AA ≥4.5)
- **Recommendation**: deepen both light amber tokens. Verified candidates: `--phosphor: #9A5700` and `--phosphor-bright: #9A5700` → buttons **4.89:1**, hover 4.89 (light-mode hover is already a color no-op today since both tokens are equal), active nav **4.62:1**, toast action `#9A5700` on tape **5.30:1**. (`#9A5F00`, the literal `≈#9A5F00` target, leaves active nav at 4.34 — just under — so land on `#9A5700`.) Update the `--phosphor-rgb` / `--phosphor-bright-rgb` triplets to `154 87 0`. Dark theme untouched (10.68:1).
- **Suggested command**: fix via implementation plan Task 1.

**2. [P1] Delete/undo toast is not announced (no live region)**
- **Location**: `src/lib/components/primitives/GlobalToast.svelte:6`
- **Category**: Accessibility
- **Impact**: `transactions.delete()` (`stores/transactions.svelte.ts:39-58`) shows "Transaction deleted." + UNDO; without `role="status"`/`aria-live="polite"` a screen reader hears nothing — a user who cannot see the toast does not know the delete happened or that it is undoable.
- **WCAG**: 4.1.3 (Status Messages)
- **Recommendation**: persistent `role="status"` container (created before content is inserted so insertion is announced), `aria-live="polite"` explicit. The ✕ dismiss button is currently an unlabeled glyph → give it an accessible name (`m.common_close()`, new i18n key).
- **Suggested command**: fix via implementation plan Task 2.

**3. [P1] Dialogs have no focus management**
- **Location**: `src/lib/components/primitives/Modal.svelte:13-29`, `ConfirmDialog.svelte:15-24`
- **Category**: Accessibility
- **Impact**: On open, focus stays on the trigger behind the modal; Tab escapes into background content (keyboard trap reversed — no trap at all); on close, focus is not restored. Also `Modal`'s `<h2>` title is not linked to the dialog (`aria-labelledby` missing), and its close button hard-codes English `aria-label="Close"` (`Modal.svelte:19`).
- **WCAG**: 2.1.2 (No Keyboard Trap), 1.3.1 (Info & Relationships), 4.1.2
- **Recommendation**: in `Modal`, bind the title `id` + `aria-labelledby`; on open, save `document.activeElement` and focus the panel (or first focusable) in a `$effect`; trap Tab within the panel; restore focus on close. Apply the same open-focus/trap/restore to `ConfirmDialog` (which already names itself via `aria-label={title}`) and add Escape close.
- **Suggested command**: fix via implementation plan Task 3.

**4. [P1] ContextMenu cannot be navigated by keyboard**
- **Location**: `src/lib/components/primitives/ContextMenu.svelte:14-42`; menu items are `role="menuitem"` buttons from callers (`transactions/+page.svelte:108-111`).
- **Category**: Accessibility
- **Impact**: `role="menu"` is exposed but ArrowUp/ArrowDown/Home/End do nothing; focus never enters the menu on open. Keyboard users can Tab into it but get no menu semantics.
- **WCAG**: 2.1.1 (Keyboard)
- **Recommendation**: on open, focus the first `[role="menuitem"]`; handle ArrowDown/ArrowUp (wrap), Home/End, Escape; restore focus to the trigger on close; add `aria-haspopup="menu"` to the trigger.
- **Suggested command**: fix via implementation plan Task 4.

**5. [P1] Autocomplete combobox has no keyboard selection**
- **Location**: `src/lib/components/primitives/Autocomplete.svelte:61-100`
- **Category**: Accessibility
- **Impact**: `role="combobox"` + `aria-expanded` + `aria-controls` are present, but the only key handled is Escape. No ArrowUp/Down to move among options, no Enter to pick, no `aria-activedescendant`. Selection is mouse-only.
- **WCAG**: 2.1.1 (Keyboard), 4.1.2 (Name/Role/Value)
- **Recommendation**: `activeIndex` state; ArrowDown/ArrowUp cycle (wrap), Home/End jump; Enter selects the highlighted option; `aria-activedescendant` on the input pointing at `{listboxId}-opt-{i}`; highlight + `onmouseenter` sync on options; reset on focus/input/select.
- **Suggested command**: fix via implementation plan Task 5.

### P2 Minor

**6. [P2] Locale toggle (VI/EN) is unnamed**
- **Location**: `src/lib/components/layout/TopBar.svelte:28-33`
- **Category**: Accessibility
- **Impact**: button announces "VI"/"EN" — an opaque abbreviation. SR users can't tell it switches the whole UI language, or what it would switch to.
- **WCAG**: 4.1.2
- **Recommendation**: `aria-label` from new i18n keys — `layout_lang_toggle_en` ("Switch to Vietnamese" / "Chuyển sang tiếng Việt"), `layout_lang_toggle_vi` ("Switch to English" / "Chuyển sang tiếng Anh").
- **Suggested command**: implementation plan Task 6.

**7. [P2] Progress bars are anonymous**
- **Location**: `src/lib/components/primitives/Progress.svelte:12-18` (has `role="progressbar"` + valuenow/min/max but **no** accessible name); callers `budgets/+page.svelte:132`, `/+page.svelte:92` (budget meter) and `:155` (goal), `goals/+page.svelte:78`.
- **Category**: Accessibility
- **Impact**: each bar announces "progressbar" with no name — users can't tell which budget/goal it belongs to.
- **WCAG**: 1.1.1 / 4.1.2 (name)
- **Recommendation**: add `label?: string` prop → `aria-label`; callers pass bucket/goal name or `m.layout_budget()`.
- **Suggested command**: implementation plan Task 6.

**8. [P2] Mobile More sheet is unnamed**
- **Location**: `src/lib/components/layout/BottomNav.svelte:71-92`
- **Category**: Accessibility
- **Impact**: the sheet is an anonymous div; the More trigger has no `aria-expanded`/`aria-haspopup`; focus never moves into the sheet.
- **WCAG**: 4.1.2
- **Recommendation**: sheet `role="dialog"` + `aria-label={m.layout_more()}`; trigger `aria-expanded={moreOpen}` + `aria-haspopup="dialog"`; move focus to the first link on open, restore on close.
- **Suggested command**: implementation plan Task 6.

## Patterns & Systemic Issues

- **One pattern**: interactive widgets get their roles/labels but **not their keyboard+focus machinery** — `role="combobox"`, `role="menu"`, `role="dialog"`, `role="progressbar"` are all present, and the missing half is uniformly *focus management + keyboard interaction + naming*. The fixes share one shape (Svelte 5 `$effect` focus lifecycle + keydown handlers), which is why a single plan covers them.
- **Second pattern**: "control that is described by an icon/abbreviation renders no accessible name" — toast ✕, locale VI/EN, budgets-page ✓/✕ edit buttons, More sheet.

## Positive Findings

- Roles and states that ARE present and correct: `aria-current="page"` on nav, `aria-expanded` on ContextMenu trigger, `role="combobox"`/`aria-controls`/`aria-expanded` on Autocomplete, `role="progressbar"` + valuenow/min/max, `aria-modal="true"`, `role="status"` on `RecoveryScreen`, `aria-label` on FAB and Modal-close.
- TopBar search input has a visually-hidden `<label>` (`sr-only`), not just a placeholder.
- FAB, BottomNav, Sidebar all expose names; the alpha-hierarchy fix means `bg-phosphor/10` active states are actually visible now.
- Text resizes and long amounts hold the `figures` monospace without overflow (spot-checked).
