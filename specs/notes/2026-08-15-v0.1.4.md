## Install on Ubuntu

```sh
sudo apt install ./notchy_0.1.4_amd64.deb
```

The deterministic artifact is produced by `pnpm release:dogfood` into `artifacts/0.1.4/`:
`notchy_0.1.4_amd64.deb` plus a `sha256sum -c`-compatible `notchy_0.1.4_amd64.deb.sha256`.

## Schema status

- Current schema: **5**
- Released source schemas that upgrade in place: **3** and **4** (older databases are rejected, never silently touched).

## Upgrade behavior

- Startup now runs a protected sequence: integrity check → schema inspection → mandatory pre-upgrade backup (only when a migration is required) → migration → post-migration verification.
- Pre-upgrade backups are written to **`backups/upgrades/`** below the app-data directory (Tauri `appDataDir()`), with names like `notchy-pre-upgrade-v4-to-v5-0.1.3-2026-08-01T00-00-00-000Z.sqlite`. A routine backup is also available manually from Settings → Backup.
- **0.1.3 → 0.1.4 is a no-migration upgrade**: both releases run schema 5, so no pre-upgrade backup is expected on this checkpoint. The mandatory backup-before-migration path is instead proven by the released-fixture **v4 → v5** coverage in the E2E suite.
- **Automatic updates are unsupported**, and **downgrades are unsupported**. A database created by a newer app version (newer schema) is refused, not migrated.

## User-visible changes

### Database recovery screen
If the database cannot be opened safely — corrupt, invalid schema, newer schema, failed pre-upgrade backup, failed migration, or failed post-migration verification — the app shows a full-screen recovery screen with the app version, latest/detected schema, live database path, and the pre-upgrade backup path. Actions: Retry, Restore from pre-upgrade backup (with confirmation), Open backup folder, Copy technical report, Quit.

### Settings → Backup
- Backup health card: app version, schema version, database path, last routine backup timestamp, last upgrade backup path, last upgrade source schema, and any warning.
- Manual "Create backup now" routine backup.
- Restore a compatible older database from a `.sqlite` file (validate → close → replace; incompatible backups are rejected with a localized message, never a raw error).
